# NELLZ DESIGN

Статический сайт-портфолио дизайнера, который делает аватарки, баннеры и
анимированные эмодзи для Telegram.

**Живая версия:** [ru](https://nellzdsg.github.io/nellz-design/) ·
[en](https://nellzdsg.github.io/nellz-design/en/)
**Автор:** [@nellzdsg](https://t.me/nellzdsg)

Коротко о проекте: 14 страниц (7 на русском в корне, 7 на английском в `/en/`),
ни одной сборки во время работы и ни одного запроса к чужому домену — шрифты,
картинки и проигрыватель анимаций лежат прямо в репозитории. Node нужен только
чтобы пересобрать CSS, Python — только чтобы подготовить картинки и анимации.

## Технологии

- **HTML + CSS + обычный JavaScript** — без фреймворков и рантайм-сборки.
- **Tailwind CSS v4** компилируется в один минифицированный `css/tailwind.css`.
  Исходник — `src/input.css`: токены дизайн-системы и компоненты.
- **[lottie-web](https://github.com/airbnb/lottie-web)** (SVG-рендер) проигрывает
  анимации, распакованные из `.tgs`.
- **Python + Pillow** — конвертация и ресайз картинок (только для подготовки файлов).
- **Node + npm** — только сборка CSS.

## Как посмотреть локально

```bash
git clone https://github.com/nellzdsg/nellz-design.git
cd nellz-design

# любой статический сервер подойдёт
py -m http.server 8000      # Windows
python3 -m http.server 8000 # macOS / Linux
```

Затем откройте http://127.0.0.1:8000/

Мелочь, о которой стоит знать: `404.html` содержит `<base href="/nellz-design/">`,
потому что GitHub Pages отдаёт эту страницу по любому несуществующему адресу и
относительные пути иначе ломаются. Чтобы проверить её локально так же, как на
проде, запустите сервер **на уровень выше** папки проекта и заходите по адресу
`http://127.0.0.1:8000/nellz-design/`. Из корня папки проекта 404-страница
откроется без стилей — это ожидаемо.

## Сборка стилей

```bash
npm install     # один раз
npm run build   # css/tailwind.css (минифицированный)
npm run dev     # то же, но с отслеживанием изменений
```

Требуется Node 20 или новее. Tailwind v4 сам находит классы в HTML-файлах,
перечислять их в конфиге не нужно. Править `css/tailwind.css` руками бессмысленно —
изменения затрёт следующая сборка; всё оформление живёт в `src/input.css`:
там токены (`--color-accent`, `--color-ink`, радиусы, тени) и компоненты
(`.btn`, `.card`, `.work`, `.lightbox`, `.stepper` и т.д.), поэтому тему можно
поменять в одном месте.

## Тексты, цены и ссылки

Обычный HTML, никаких шаблонизаторов. Правки нужно вносить **в обе версии** —
в корне и в `en/`, иначе языки разъедутся.

Часто встречается в нескольких местах одно и то же, поэтому список для сверки:

- цены и условия — `services.html`, `en/services.html` (карточки и калькулятор),
  плюс короткая строка с ценами на главной;
- ссылки на соцсети — шапка и подвал каждой страницы, `about.html`,
  `contact.html` (и их английские версии);
- вопросы и ответы — `faq.html` / `en/faq.html` **и** JSON-LD `FAQPage` в той же
  странице: если правите вопрос, поправьте и разметку;
- `canonical`, `og:url`, `hreflang` — в `<head>` каждой страницы и в `sitemap.xml`.

### Калькулятор заказа

Это один блок на `services.html`, вся конфигурация — в атрибутах, JavaScript
менять не нужно:

```html
<div id="calc"
     data-currency="$"  data-discount-from="3"  data-discount-rate="0.2"
     data-telegram="https://t.me/nellzdsg"
     data-msg-intro="Здравствуйте! Хочу заказать:"
     data-msg-item="{name} × {qty} — {sum}">
  <div data-calc-key="avatar" data-name="Аватарка" data-price="6">
    <button data-calc-minus>−</button>
    <span data-calc-count>0</span>
    <button data-calc-plus>+</button>
  </div>
  …
</div>
```

- строка позиции — любой элемент с `data-calc-key`, `data-name` и `data-price`;
  внутри него `[data-calc-count]` показывает количество, `[data-calc-minus]` и
  `[data-calc-plus]` его меняют;
- `data-discount-from` — от какого количества позиций включается скидка,
  `data-discount-rate` — её размер (0.2 = 20%);
- подстановки в шаблоне позиции: `{name}`, `{qty}`, `{sum}`; в подписи скидки —
  `{percent}`;
- чтобы добавить четвёртую услугу, достаточно скопировать строку позиции.

### Галерея, лайтбокс, фильтры

- плитка работы — кнопка с `data-lightbox-item` и `data-category` (`avatars`,
  `banners`, `emoji`); `data-full` — путь к большому изображению, `data-alt` — подпись;
- фильтр — элемент с `data-filter="avatars"` (`all` показывает всё);
- анимированные плитки вместо картинки несут два атрибута: `data-lottie-src`
  (что проигрывать в лайтбоксе) и `data-lottie` на внутреннем элементе
  (что проигрывать прямо в сетке). Список для листания собирается из видимых
  плиток, поэтому скрытые фильтром работы не попадают в лайтбокс;
- `#lightbox-counter` показывает «текущая / всего», стрелки и `Esc` работают
  с клавиатуры.

## Как добавить работу или эмодзи

Скрипты подготовки не обязательны: оптимизированные `.webp` и `.json` уже лежат
в репозитории. Но если нужно добавить своё, порядок такой.

**Нужен Python 3 и Pillow:**

```bash
py -m pip install pillow
```

**Работы.** Исходники не хранятся в репозитории (папка `моё-портфолио/` в
`.gitignore`), поэтому после клонирования её нужно создать. Скрипт
`scripts/optimize_images.py` ищет в ней папки с исходниками и сверяет имена
файлов со списками `AVATARS` и `BANNERS` в самом скрипте, превращая их в
латинские слаги:

1. положите файлы в `моё-портфолио/аватарки` или `моё-портфолио/баннеры`;
2. допишите пару «имя файла → слаг» в `AVATARS` / `BANNERS` в
   `scripts/optimize_images.py`;
3. выполните `py scripts/optimize_images.py` — появятся
   `assets/img/works/avatars/<slug>-thumb.webp` и `-full.webp`
   (аватарки 640 и 1400 px по длинной стороне, баннеры 960 и 1920 px);
4. добавьте плитку в `portfolio.html` и `en/portfolio.html` по образцу соседних.

Портрет автора и обложка ролика подхватываются по префиксу имени файла
(`PERSONAL_PREFIX` и `VIDEO_COVER_PREFIX` в том же скрипте), а значок сайта
(`favicon.ico`, `favicon-32.png`, `apple-touch-icon.png`) и `og-image.jpg`
для превью ссылок рисуются программно из `assets/img/ui/brand-monogram.png`
(он лежит в репозитории, из исходников не берётся). Скрипт идемпотентный:
повторный запуск безопасен, оригиналы не изменяются.

**Эмодзи.** `.tgs` — это обычный gzip от Lottie JSON, поэтому «конвертация» —
это распаковка:

1. положите файлы в `моё-портфолио/анимированные эмодзи`;
2. выполните `py scripts/prepare_lottie.py` — рядом появятся `js/lottie/emoji-N.json`
   (нумерация по алфавиту файлов);
3. добавьте плитку в галерею с `data-lottie` и `data-lottie-src`.

## Публикация

GitHub Pages раздаёт ветку `main` из корня репозитория, никаких workflow нет:
достаточно запушить изменения, и через минуту-другую сайт обновится.

Если делаете **свою копию** сайта, перед публикацией стоит поправить три вещи:

1. адрес в `<base href="…">` внутри `404.html` (и `en/404.html`) — там зашит
   `/nellz-design/`;
2. адреса в `canonical`, `hreflang`, `og:url` в `<head>` всех страниц и
   в `sitemap.xml` + строку `Sitemap:` в `robots.txt`;
3. при переезде на собственный домен — добавить файл `CNAME` с именем домена.
